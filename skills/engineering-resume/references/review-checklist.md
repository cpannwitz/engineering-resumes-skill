# Review checklist

Used by Review mode. Score each area 0–2 (0 = fails, 1 = partly, 2 = meets), then report
findings ordered by **impact on getting an interview**, not by checklist order. Pick the rule set
first (English → `formatting.md` + `sections.md`; German → `german-lebenslauf.md` overrides).

## A. First impression (6-second test)
- [ ] Target role obvious from the top third (title line, most recent role, or summary)
- [ ] Strongest, most relevant content sits top-left
- [ ] Length fits seniority (EN: 1 page / 2 senior; DE: 1–2 pages)

## B. Layout and typography
- [ ] Single column, no graphics/icons/skill bars (photo only if DE and intended)
- [ ] Clear, consistent section breaks and spacing; no cramming
- [ ] Readable font ≥ 10.5 pt, black; margins ≥ ~1 cm; not justified
- [ ] Emphasis sparse and not stacked; no bolded keywords in bullets
- [ ] Dates aligned consistently (EN right; DE left column or right)

## C. Header and contact
- [ ] Plain-text contacts, no labels, no `https://www.`, no hidden links
- [ ] Only useful items (EN: no address, phone/LinkedIn optional; DE: phone, city, LinkedIn/XING expected)
- [ ] GitHub/portfolio linked only if current and presentable
- [ ] No bias-inviting personal data (EN); DE personal data kept to optional minimum

## D. Section order and naming
- [ ] Order matches career stage (`sections.md` table)
- [ ] Standard section names; no references section
- [ ] Summary present only when justified (EN) / Kurzprofil concise (DE)

## E. Experience bullets (highest weight — counts double)
- [ ] Accomplishments and problems solved, not duties
- [ ] Strong past-tense verbs; none of the weak/inflated verbs
- [ ] Impact shown with real numbers or concrete scope; metrics early
- [ ] 1–2 lines, no orphan words, no periods, no pronouns, digits for numbers
- [ ] Engineering skill leads, tools support; integration over parts lists
- [ ] Best bullets first; relevant to the target role
- [ ] No filler adjectives/adverbs

## F. Skills
- [ ] ≤ ~3 grouped lines, comma-separated, correct capitalisation, `C, C++` not `C/C++`
- [ ] Every listed skill is backed by a bullet, and key bullet tech appears here
- [ ] No soft skills, no assumed basics, no proficiency labels

## G. Projects and education
- [ ] Projects are real, linked where possible, bullets not paragraphs
- [ ] Education format matches rule set (EN graduation date only; DE range + degree name + grade optional)
- [ ] No high school (EN) / Abitur only early career (DE)
- [ ] Studies without degree handled per rule set (EN omit or one coursework line; DE listed as "ohne Abschluss")

## H. Dates and consistency
- [ ] One date format throughout; en dash with spaces; Present / heute
- [ ] No gaps left unexplained (DE especially)

## I. Language quality
- [ ] No typos or grammar errors; consistent tense and terminology
- [ ] Abbreviations spelled out on first use

## J. Honesty
- [ ] Nothing in the rewrite goes beyond what the user stated; all `[?]` placeholders listed

## Report format

```
# CV review — <name>, <rule set: EN | DE>
Score: <sum>/22  (E counts double)

## Top fixes (do these first)
1. <finding> — <why it matters> — before → after

## By area
| Area | Score | Notes |
|---|---|---|

## Bullet rewrites
| Before | After | Needs from you |
|---|---|---|

## Open questions for you
- <missing metric / unclear scope>
```
